# Feedless v0.2 — Design Spec

**Date:** 2026-07-10
**Status:** Pending user review
**Baseline:** v0.1.0 (all 19 toggles live-tuned, commit b941f35)

## Overview

Seven additions that turn v1's "it hides things" into a product: a placeholder
card with user-set intention text, per-platform snooze, selector
self-diagnosis, a maintainer doctor script, a master-toggle keyboard shortcut,
uninstall feedback, and release/repo hygiene (test-gated releases, issue
template, AMO source notes, privacy policy).

**Non-goals (this release):** Threads support (v0.3), actual store submission
(M4 — follows this release), locale-aware anchors, quotes library.

## 1. Placeholder card ("intention card")

When a platform's feed feature is enabled and the user is on the home page,
the content script injects one card where the feed was.

- **Content:** 🌿 + "Feed hidden" + the user's intention text (if set), e.g.
  *"Reply to DMs, then leave."* One global intention string, set in the popup
  (single-line text input under a new "Intention" section).
- **Injection:** `insertCard(platform)` runs after the engine stamps; inserts
  `<div data-feedless-card>` with a **shadow root** (Meta's CSS cannot leak
  in, ours cannot leak out) as the first child of `main` (IG) / the marked
  feed container's parent (FB). Idempotent (one card max); removed when the
  feed feature is toggled off or the platform is paused/snoozed (reacts via
  the existing settings watch).
- **Visibility rule:** card shows only when `data-df-path="home"` AND the
  platform's feed feature is effectively on. CSS gates it exactly like other
  rules: `html:not([data-df-ig-feed]) [data-feedless-card] { display: none }`
  is NOT needed — the content script adds/removes it directly on settings
  changes (simpler, and the card is ours, not Meta's).
- Card styling: system font, centered, muted colors, dark-mode aware via
  `prefers-color-scheme`.

## 2. Snooze (per-platform, 3 durations)

- **Settings schema (backward-compatible, stays `v: 1`):**
  ```ts
  interface Settings {
    v: 1;
    features: Record<string, boolean>;
    intention?: string;
    snooze?: Partial<Record<Platform, number>>; // epoch ms; absent/past = not snoozed
  }
  ```
- **Semantics:** `isPlatformActive(s, platform, now)` = master switch on AND
  `(s.snooze?.[platform] ?? 0) <= now`. `computeAttrs` takes `now` and returns
  `[]` while snoozed (whole platform shows stock, same as master-off).
- **Engine:** on stamp, if snoozed, schedule `setTimeout` for the remaining
  time to restamp at expiry (cleared/rescheduled on settings changes; capped
  at 2^31-1 ms). New page loads compute freshly, so timers are per-tab
  conveniences, not the source of truth.
- **Popup:** per-platform row: `⏸ Pause on <Platform>: [5m] [30m] [1 day]`.
  While snoozed: "Paused — resumes in 27m [Resume now]" (countdown, 1s tick),
  feature list gets the existing `.paused` treatment.
- Writes via a new `setSnooze(platform, untilEpochMs | null)` in storage lib.
- **Testability:** all snooze logic takes `now` as a parameter; no Date.now()
  in pure functions (tests pass fixed timestamps; only thin callers read the
  clock).

## 3. Selector self-diagnosis

- Content script, ~5 s after `document_idle`-ish (setTimeout post-stamp):
  for each **enabled** feature, evaluate its CSS rules **whose path guard
  matches the current page**; if every applicable selector matches 0 elements,
  record a hit.
- **`CssRule.mayBeAbsent?: boolean`** — set on rules that legitimately match
  nothing (notification badges when read, marker rules, legacy fallbacks like
  FB's `div[role="feed"]`). Excluded from diagnosis. A feature counts as
  "suspect" only if ALL its non-`mayBeAbsent` applicable rules matched 0.
- **Storage:** `storage.local` (device-local, not synced) key `diagnostics`:
  `Record<featureId, { days: string[] }>` — up to 5 distinct ISO dates on
  which the feature was suspect; cleared for a feature the first time it
  matches again.
- **Popup:** features suspect on **≥ 3 distinct days** get a ⚠ next to their
  toggle and one shared banner: "Something may be broken — report it" linking
  to the GitHub issue template prefilled with feature id + extension version
  (opens a tab only when clicked; zero automatic network traffic).

## 4. Doctor script (maintainer tool)

`scripts/doctor.ts` (bun + Playwright, local only, never CI):
- Launches headful Chromium with a **persistent profile** at
  `.cache/doctor-profile/` (gitignored) — log in once, reuse thereafter.
- Visits per-platform pages (IG: home, reels, explore, a post; FB: home) and
  prints a table: feature / rule selector / match count / visible count —
  the automated version of this week's manual verification.
- Flags: `--platform ig|fb`, `--page home|post|...`. Documented in README
  under "Maintenance".

## 5. Keyboard shortcut

- Manifest `commands`: `toggle-site` (suggested key **Alt+Shift+F**),
  handled in the background: query active tab URL → if instagram/facebook,
  flip that platform's master switch. Open tabs update instantly via the
  existing storage watch. No response UI (the page visibly changing is the
  feedback).

## 6. Uninstall feedback

- Background, on startup: `browser.runtime.setUninstallURL()` pointing to the
  GitHub issue template for feedback. The only "telemetry" is a page the
  user's browser opens after uninstalling; nothing is sent by the extension.

## 7. Release & repo hygiene

- **release.yml:** add `bun run compile && bun run test` before the zip steps
  (a `v*` tag on a red commit must fail, not ship).
- **.github/ISSUE_TEMPLATE/broken-selector.yml:** structured form — platform,
  page URL pattern, which toggle, what became visible, extension version.
  Plus `config.yml` disabling blank issues, linking the template.
- **docs/amo-source-notes.md:** Firefox AMO reviewer instructions
  (bun install / generate / build — byte-reproducible output).
- **PRIVACY.md** (repo root): "Feedless collects nothing" policy — no
  analytics, no network requests, storage permission only, settings stay in
  the user's browser/sync. Linked from README; used as the store listing's
  privacy URL.
- **docs/store-listing.md:** draft Chrome/AMO listing copy (M4 prep),
  including the "English-language Meta UI supported at launch" limitation
  note and no-Meta-trademark asset guidance.

## Testing

- Unit: snooze semantics (fixed timestamps: active/expired/absent, master
  interplay), settings backward-compat (old `{v:1, features}` blobs parse;
  new fields optional), card insert/remove reacting to settings, diagnosis
  (suspect only when all non-`mayBeAbsent` applicable rules miss; day-streak
  accumulation; reset on match), popup snooze buttons write `snooze`,
  intention input writes `intention`.
- e2e fixtures: unchanged selectors keep passing; card excluded (injected,
  not fixture-testable).
- Manual: verify-checklist gains snooze + card + shortcut walk-through.

## Version & release

Ships as **v0.2.0** (tag → release zips, now test-gated). Store submission
(M4) follows using PRIVACY.md + store-listing.md + fresh screenshots with the
intention card visible.
